# Telemetry implementation and release qualification — 0.7

## What changed

The application and reliability worker now use the same new passive platform collectors. Scan coverage separates automatic checks from four guided/external check types: processor integrity, physical RAM integrity, visual/VRAM integrity, and physical battery inspection. A cancelled automatic collector remains a collection gap. Reliability coverage separately reports readable sources, unavailable sources and confirmed hardware exclusions. Readable measurements can have an unassessed condition; collecting a temperature does not establish a healthy component.

These are implemented adapters, not an assurance that all OEMs expose every field. macOS and Windows packages include the drive reader; Linux packaging continues to require a separately installed smartmontools tool. Neither package installs a kernel sensor driver, starts a diagnostic daemon, changes SMART settings, restarts a service or automatically requests elevation. Monitoring and notifications remain separate opt-ins; repairs require approval.

## Attribution and interpretation rules

- Never assign raw disk logs by assuming `Get-PhysicalDisk.DeviceId` is the Win32 disk index. Both inventories must have a unique, matching nonempty serial; the raw reader must return that serial as well. Serial values are discarded after validation.
- ACPI values are tenths Kelvin. A thermal zone is not necessarily the CPU. Missing/disabled/sentinel readings remain unavailable. Only a usable OEM critical trip produces a thermal assessment.
- A fan at zero RPM may be intentionally stopped. Provider temperature/voltage/fan readings without device thresholds remain readable but unassessed.
- Native macOS thermal states report system thermal pressure, not component temperature or wear. Memory pressure, paging, clock speed and OOM history identify resource/workload leads, not failed silicon.
- A stopped launchd job with positive last exit becomes a historical investigation lead. Running jobs, zero-exit on-demand stops and negative signal statuses do not become failed-service findings. Root/system launchd jobs are outside the user-domain scope.
- Retained Windows events inspect bounded IDs, severity and timestamps, not message bodies. Empty memory-result history is not a passing RAM test; even informational result metadata does not establish full physical integrity.
- NVIDIA ordinary readings and ECC queries fail independently. Unsupported fields are absent rather than zero. Confirmed absence of NVIDIA from a readable hardware inventory is excluded from required coverage; failure to enumerate hardware is not proof of absence.
- AMD RAS requires both explicit corrected and uncorrected counters. Missing, duplicated or malformed counters are unassessed. No error injection or driver recovery control is used.
- Unsafe shutdowns, power cycles and lifetime written bytes are context. They do not independently produce a replacement recommendation or remaining-life forecast. NVMe data units are converted using 512,000 bytes per unit.

## Primary-source research

- [Apple ProcessInfo thermalState](https://developer.apple.com/documentation/foundation/processinfo/thermalstate-swift.property): official system thermal pressure API. A small universal Swift helper also enumerates Metal devices.
- [Apple XNU memory pressure documentation](https://github.com/apple-oss-distributions/xnu/blob/main/doc/vm/memorystatus_notify.md): normal/warning/critical pressure levels, used separately from physical integrity.
- [Apple launchctl manual source](https://github.com/apple-oss-distributions/launchd/blob/main/man/launchctl.1): documented list columns and last-exit interpretation. Unstable `launchctl print` formatting is not parsed.
- [Microsoft storage reliability counters](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-storagereliabilitycounter): provider temperature, maximum normal operating temperature, power hours, error and latency fields. Windows Wear is preserved separately from the standardized NVMe PercentageUsed field.
- [Microsoft thermal platform design guide](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/design-guide) and [Win32_TemperatureProbe limitations](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-temperatureprobe): use firmware zones, not an often-unpopulated generic CPU-temperature property.
- [LibreHardwareMonitor upstream](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor): optional existing Windows sensor source. Its driver is not bundled or installed by PC Health.
- [NVIDIA management query reference](https://docs.nvidia.com/deploy/nvidia-smi/): independent operational and ECC/retirement queries; capability depends on GPU and driver.
- [Linux AMDGPU RAS documentation](https://www.kernel.org/doc/html/latest/gpu/amdgpu/ras.html): read-only corrected/uncorrected sysfs counters. Recovery and error injection interfaces are not used.
- [Linux PSI documentation](https://www.kernel.org/doc/html/latest/accounting/psi.html): some/full stall percentages and averaging windows.
- [smartmontools official 7.5 distribution](https://sourceforge.net/projects/smartmontools/files/smartmontools/7.5/): pinned source and official Windows executable. The GPL license and corresponding source archive accompany the packages.

The earlier papers and reliability architecture remain in [RELIABILITY_RESEARCH.md](RELIABILITY_RESEARCH.md). These API changes improve observable evidence; they do not validate predictive ML or physical self-repair.

## Packaging and qualification

`npm run dist:mac` creates a universal arm64/x86_64 macOS 13+ DMG and ZIP. `npm run dist:win` creates Windows x64 NSIS and ZIP packages. The runtime, UI, fonts, rules, catalog and platform diagnostic helpers are included. Build-time downloads require internet; installed scans do not.

Source regeneration: `npm run vendor:prepare` verifies pinned upstream checksums and rebuilds universal macOS smartctl on macOS; it extracts the Windows executable without running its upstream installer. `npm run build` rebuilds the native Swift helper on macOS. Binary/source/license locations and build commands are in [vendor/NOTICE.md](vendor/NOTICE.md).

Developer ID signing/notarization and Windows Authenticode credentials have not been provided. macOS has an ad-hoc integrity signature; it has no Developer ID signature or notarization. Windows has no Authenticode signature. These are development-preview distributions and can trigger Gatekeeper/SmartScreen warnings. Windows and Intel Mac real-hardware qualification remains required; parser tests and successful cross-packaging do not establish target-device compatibility. No public upload, update server or signing certificate is created by this work.

## Local validation results

The development Apple M1 host completes 12/12 automatic scan checks, with four external inspections kept separate. The bundled reader exposes standardized NVMe health/endurance/error/lifecycle fields without elevation on this device. This does not imply that other controllers or OSes permit the same raw access. Unit tests exercise malformed and missing input, explicit zero counters, ACPI conversion, attribution, service intent, coverage states and historical-schema compatibility. Desktop tests exercise real scans, isolated monitoring and headless collection; accessibility and layout checks cover the existing UI. Packaged validation uses a temporary profile and verifies bundled resources plus actual helper/worker execution.
